### Edge cases observed

| Case | Behaviour |
|---|---|
| Unknown `Goal` string | Accepted; encodes to all-zero one-hot, low confidence (0.130). The app rejects unsupported values before inference. |
| Empty `Goal` string | Same all-zero behaviour. |
| `Gender = Unspecified` | Accepted as an all-zero one-hot vector. Documented and intentional for users who prefer not to say. |
| BMI far outside training range | Model still returns a prediction. The app clamps weight/height and warns; it does not treat the output as medical advice. |
| Integer passed to a string input | Rejected by ONNX Runtime with `INVALID_ARGUMENT`. The inference service always constructs string tensors. |

## 7. Inference performance in the browser

A real browser run of the deployed ONNX artifact (Chrome, WASM) produced:

- Plan category: **Push-Pull-Legs Split (Hypertrophy)** for a 31-year-old, 78 kg, 178 cm, intermediate, gym, no-injury, muscle-gain profile.
- Inference time: **14.7–17 ms** after WASM initialisation.
- No console exceptions.

## 8. What these results do not establish

- They do not show the recommendation is safe, effective, or clinically appropriate.
- They do not validate the exercise-selection or safety rules; those are tested separately with unit tests and are rule-based by design.
- They say nothing about users outside the synthetic training distribution.
- They do not replace a prospective evaluation with real athletes and qualified supervision.
